# 创作罗盘（暂名） P0.3 · 交互原型评审

## 这次交付是什么

**仅用于评审的独立可交互原型，不是正式软件0.3发行版。** 正式应用、模型接口、客户数据及运行服务不属于本次改动范围。评审通过后，再确定是否研发以及研发边界。

原型采用HTML/CSS/JavaScript本地文件，无需安装依赖或启动服务器。

工具面向所有用户开放；此历史原型以「财经笔记」和虚构财经内容演示流程，不代表用户实际已选方向或所有用户默认配置。

入口：[打开交互原型](<index.html>)。请使用浏览器打开，三个页面资源文件应保留在同一目录。不要只下载一个HTML而遗漏脚本和样式。

## 商业模式已经纠正

```text
工具内置服务商入口与接入预设
        ↓
用户去选定服务商官网注册、充值
        ↓
用户把自己的API Key填回工具
        ↓
工具使用用户选择的服务商和模型生成内容
```

- 模型费用由服务商向用户收取，资金不经过本项目。
- 工具不建立平台模型余额，不代充值、不代扣款、不做模型消费结算。
- 推广收入可能来自广告合作、邀请注册、服务商确认的消费分成；归因与结算按实际合作协议，不虚构已达成合作或收入金额。
- 推荐入口不等于已连接；用户仍需完成自己的服务商配置。
- 普通用户看接入与内容生产，不承担项目运营者的佣金管理工作。

## 信息架构

| 页面 | 解决的问题 |
| --- | --- |
| 今日工作台 | 今天要生成什么、当前缺什么配置、生成进度及任务状态 |
| 模型服务商 | 推荐入口、已添加服务、模拟连接、自定义服务、默认模型分配 |
| 账号与自动化 | 一次设置品牌/读者/内容目标/语气，查看模拟每日每周计划 |
| 内容与发布 | AI推荐主推题、可视文章、整组图卡、改稿审核、复制下载和手动发布指引 |

Markdown、接口地址和复杂设置不应成为日常使用的第一屏；用户也不必每天先提供选题和观点。

## 建议按这条路径评审

1. 从未配置状态进入工作台，看是否能明白“先连接模型服务商”。
2. 进入推荐服务商，点击接入；查看“去服务商官网注册/充值”的模拟离站说明。
3. 使用演示Key，选择模型并模拟测试连接成功；观察是否进入“已添加服务”，以及默认用于选题/写作的状态。
4. 回工作台模拟生成。观察自动推荐三个方向、选择主推题、形成论点及两平台内容的流程是否清楚。
5. 在内容页先读可视稿，不展开Markdown或原始数据也应知道文章想表达什么。
6. 修改文字或图卡，检查未保存提醒、保存反馈、审核状态撤回是否容易理解。
7. 检查公众号复制操作和小红书图片下载/文案复制的位置、说明是否明确。
8. 演示完成审核及手动发布归档，确认不会误以为已经自动发布。

## 也要看失败路径

- 模拟连接失败：是否告诉用户检查配置，而不是说已经连接？
- 模拟服务商额度不足：是否明确去服务商官网充值，而不是给项目充值？
- 没有可用默认模型：生成是否被引导回设置？
- 删除正在使用的默认服务：是否有确认或影响说明？
- 自定义服务商URL无效：是否被拦截，而不是接受任意脚本地址？
- 未保存改稿：是否禁止复制旧版本、下载旧图和批准？
- 剪贴板权限不可用：是否给出可手工复制的内容，而不是谎报复制成功？

## 原型的模拟边界

- 所有服务商、模型、连接结果、生成内容、交易数据与任务状态均为演示。样稿是预置内容，用来评审表达结构和流程，不会根据偏好真正调用AI推理。
- 不调用真实模型，不打开真实充值页面，不接支付，不创建实际定时任务，不向平台发布。
- 不输入真实Key。演示输入仅用于界面流程，不应写入本地存储或导出文件。
- 点击复制可能在浏览器允许时复制演示内容；权限不可用时走手工复制提示。
- 点击下载可以生成带演示标识的本地文件，用来评审操作手感，不代表生成了可发布真实分析。
- 会话内状态可恢复初始；刷新后不承诺保留配置。正式版存储方案待评审后确定。
- 推荐服务商卡片不是实际厂商合作声明；真实服务商名称、链接和推广参数须在合作确认后另行配置。

## 本次不设计/不实现

- 平台钱包、充值订单、模型代扣、Token售价、充值退款及算力计费后台。
- 运营者佣金结算后台、支付渠道、真实推荐关系与用户行为上报。
- 实际供应商鉴权、密钥加密存储、模型列表同步和真实网络故障切换。
- 正式发布接口、公众号/小红书账号授权、真实内容质量验收。
- 正式应用的数据迁移、版本发布或部署变更。

## 请重点决定的事项

1. **服务商入口**：推荐服务商和已添加服务的分区是否符合直觉？推荐/推广标识是否清楚但不过度干扰？
2. **接入步骤**：预设接口地址，用户只填Key和选模型的流程是否足够简单？
3. **模型分配**：默认同一服务完成选题和写作，仍允许分配不同模型，是否合适？
4. **工作台主线**：是优先看今日内容，还是优先显示配置状态？未配置状态是否容易开始？
5. **内容与发布**：文章、图卡、审核与复制下载的位置，是否能让你直接理解如何去平台发布？
6. **研发范围**：评审后先实现哪些页面与能力，哪些仍保留为后续项？

**评审通过不等于所有演示能力已经研发完成。** 下一阶段应以评审意见形成明确研发清单，再决定接入哪些真实服务商与推广合作。
